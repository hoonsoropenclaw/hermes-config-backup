# Raphael Harness Pitfalls（2026-10-11 補）

補主 SKILL.md 沒寫到的 4 個實戰細節。**每跨天專案 / 全十步循環前必看**。

## 1. workdir CJK 觸發 terminal workdir 阻擋的快速繞路

`terminal(workdir="…會議錄音…")` 會被擋下：「Blocked: workdir contains disallowed character '會'. Use a simple filesystem path without shell metacharacters.」（與 pitfalls-2026-10-08 第 3 條一致）

**快速繞路（不需改環境變數）**：
```bash
# 把要跑的檔 cp 到 ASCII 路徑，workdir 用 ASCII 路徑
cp /home/.../workspace/<CJK-id>/meeting_pipeline.py /tmp/mp_test.py
python /tmp/mp_test.py --help              # workdir 用 /tmp 就 OK
```

**比 env var 改 PATH 快的理由**：1 次 cp + 1 次 python 完成；改環境變數要 unset 後再 export，且只影響當下 terminal 呼叫。

**事後**：測試輸出 / RUNLOG.md 仍可寫回 CJK 路徑（write_file/patch 不受 CJK 限制），不影響交付。

## 2. sandbox 工具試用前先 pip install 到 dev 環境（不污染 root）

`pydub` 之類套件在 N100 dev 軌預設沒裝。實作 meeting pipeline 時第一個錯就是 `ModuleNotFoundError: No module named 'pydub'`。

**正確流程**：
```bash
pip install pydub --quiet
python -c "from pydub import AudioSegment; print('pydub OK')"   # 確認可 import
```

**為什麼不裝到 `sandbox/venv/`**：sandbox/ 是「外部工具隔離區」（AGENTS.md 鐵則 6），用於「從 GitHub 下載的工具試用」；自家 pipeline 的依賴走 root pip 更順。pip list 之後可選擇性把依賴寫進 `requirements-dev.txt` 讓使用者知道。

## 3. eval judge pending_manual ≠ 作品失敗（2026-10-10 規則的強化版）

`eval judge` 回 `pending_manual`：
```json
{"ok": true, "pending_manual": [{"judge": "claude", "reason": "手動評審：等待外部評審..."}], "gate": {"pass": false, "threshold": 75.0, "hard_fail": false}}
```

**注意 `pass: false` + `hard_fail: false` 的組合**：
- `pass: false` 是因為 self_total < threshold（預測 70、自評 65.4 都低於 75）
- `hard_fail: false` 表示**不是** hard_fail（沒「沒執行就宣稱可用」或「程式碼含金鑰」等自動擋下條件）

**處理**：
1. ✅ **不要 retry** `eval judge`（pending_manual 是 reviewer 排程狀態，重試只會再 pending）
2. ✅ **不要編造**一個高分（pitfalls-2026-10-10 規則）
3. ✅ **繼續往下跑**：reflect → journal → metacognition → publish
4. ❌ **不是真的失敗就別卡住**：本日 score 偏低可能是預測高估（Day 1/3 only），不是作品真壞；record 後等下次 cycle 再校準

**對照「真失敗」**：
- 真失敗 = `gate.hard_fail: true` 或執行 throw → 走 `sop propose` 修流程
- pending_manual = reviewer 缺席 → 正常交付流程繼續

## 4. 跨天專案 `--predicted` 要按階段比例，不是完成品

跨天專案 Day 1 of 3，artifact add 給了 `--predicted 70` → 自評 65.4、self_total < threshold 75 → `gate.pass: false`。

**預測分數正確算法**（避免 prediction_bias 累積）：
```
predicted = round(remaining_days / total_days * scope_complete_pct * type_historical_mean)
```

實例（Day 1 of 3, code type, 過去 mean ~65）：
```
predicted = round(1/3 * 0.4 * 65) = round(8.7) ≈ 9   # 太低，看 scope 而非時間
```

更好的算法（按 scope 完成度）：
```
scope_pct = stages_done / total_stages   # 1/4 = 0.25
predicted = round(scope_pct * type_historical_mean * 1.1)
           = round(0.25 * 65 * 1.1) = round(17.9) ≈ 18  # 還是不對
```

再修（用 completed_stages × weight，而不是 mean）：
```
predicted = sum(criterion_weight * anchor_score) for completed criteria
```

**最實用的算法**（經驗法則）：
| 階段 | predicted 範圍 |
|---|---|
| Day 1 of 3 (scaffolding + 1-2 stages) | 50-60 |
| Day 2 of 3 (main stages done) | 65-75 |
| Day 3 of 3 (最後整合 + 測試 + RUNLOG) | 80-90 |

**`predict_high_then_self_low` 的後果**：`calibrate` 的 prediction_bias 累積 → 之後 plan 對你會自動打折預測分數 → 把好作品低估。**Day 1 就誠實給 50-60 比最後給 90 真實準很多**。
